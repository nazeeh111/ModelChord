## Consequential findings sent to builder

1. **Freeze coverage is incomplete in reviewed source.** `freeze()` binds core numerical code, `run_study.py`, main ledgers and artifact weights, but omits `examples/text_features.py`, artifact manifests, adapter metadata/factors and deployment selection. These participate in preprocessing, interpretation or export selection. They should be included before confirmation, together with an immutable snapshot of any protocol version referenced by source manifests.
2. **Confirm does not verify current dataset identity.** `confirm()` recomputes vision/SMS data but does not compare the live content hash against the locked digit `source_sha256` and SMS `zip_sha256`. It recomputes the text confirmation split rather than asserting the resulting IDs equal the frozen ledger. Add those checks before constructing/evaluating confirmation batches.
3. **Some recipe registry rows lack identities.** In the reviewed registry, strongest repair, ablations and controls have no artifact/report identity, and pilot/main names collide by suite/seed/name. Artifact paths distinguish ordinary baselines, but not those rows. Bind run phase/version, artifact path, artifact/manifest hashes and repair-report hashes where applicable; retain pilot and diagnostic attempts explicitly.
4. **RegMean parent-forward cost is understated.** The reviewed baseline row says `teacher_calls=0`, although RegMean invokes each expert's activation forward once. Report three expert forward calls and 537 example forwards, or define zero distillation calls separately from activation collection. Include calibration activation accesses in total examples evaluated. Repair itself uses zero parent forwards.
5. **Strongest repair lacks an equally matched full-weight comparator.** Seed 11 arithmetic repair uses 537 gradient accesses; strongest repair uses 716 and starts from another ordinary model. Existing joint/target-matched baselines match the arithmetic repair. This is suitable for that comparison, but strongest-repair superiority cannot be attributed against those unmatched comparators. Add a corresponding baseline or label the strongest-start result as unpaired.
6. **Protection reference must remain explicit.** Clean protection is relative to the selected ordinary model, plus an absolute .88 floor, rather than a .02 allowance from the clean base. Report both base and ordinary clean regressions and register what base degradation is acceptable. A claim of protecting base capability within .02 would be false under the current definition.

These were reported before confirmation. Builder remediation needs a final source/lock readback; the presence of this document does not mean those changes have already occurred.

## Budget and measurement limits

The added ordinary joint-mixture baseline begins at the same selected arithmetic artifact and matches repair gradient steps, total example accesses and zero teacher calls. Its pool contains equal-size domain slices; sampled minibatches are not guaranteed exactly balanced. Three learning rates are selection-tuned. The target-sequence-matched baseline is retained separately. Repair tests many more candidate interventions on selection data; its selection-compute budget is not equal to the joint baseline's. The protocol discloses this, so describe the comparison as matching gradient data/steps, not fully compute matched.

The no-priority ablation consumes more gradient examples than deficit-prioritized repair because it differentiates all domains. Report its cost alongside quality; it does not isolate priority under exactly equal gradient-access cost. Fixed rank changes actual rank usage; show achieved rank as well as the common upper bound.

`latency()` measures a warm cached-model forward including all dense heads/folded corrections. It excludes preprocessing, loading, CLI startup and export. Label that boundary. A fresh build-resource script measures the composer separately from expert training and checks exact weight reproduction. Confirmation-process peak RSS alone would not measure training/build peak. Total stored bytes must include artifact manifests and retained adapters, while deployment-only size should identify the selected standalone artifact.

No study superiority conclusion is supported before the locked confirmation is evaluated. Negative repairs and unmet floors are valid measurements, but must remain labeled `no acceptable candidate found`. This review does not promote a frontier model to a floor-satisfying model, and does not establish all original release gates.
